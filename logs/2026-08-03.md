## 💡 배운 점 & 트러블슈팅

1. **PostgreSQL psql 접속 시 데이터베이스 지정 필수**:
   - `psql` 접속 시 `-d runner_db` 옵션을 빠뜨리면 기본 DB(`postgres`)로 들어가 테이블이 보이지 않는 현상 경험. `-d` 옵션을 명시하여 해결!
2. **Git PR(Pull Request) 병합 및 GitHub Desktop**:
   - `main` 직접 푸시가 아닌 `feature/*` 브랜치에서 작업 후 PR 병합하는 현업 워크플로우 경험.
3. **JWT secret 비밀키 생성 원리 & yml 설정값 개념**:
   - **비밀키 생성 원리 및 방법**: JJWT 0.12.x 암호화 표준에 따라 최소 256비트(32바이트) 이상의 무작위 바이트 스트링을 Base64 인코딩하여 생성됨.
     - **방법 1 (Git Bash)**: `openssl rand -base64 32` 실행
     - **방법 2 (PowerShell Python)**: `python -c "import secrets, base64; print(base64.b64encode(secrets.token_bytes(32)).decode())"` 실행
   - **`jwt.secret`**: 서버만 알고 있는 마스터 암호키. 토큰의 위변조 여부(서명/Signature)를 검증함.
   - **`access-token-expiration` (1,800,000ms = 30분)**: API 호출 시 사용하는 짧은 수명의 인증 토큰.
   - **`refresh-token-expiration` (1,209,600,000ms = 14일)**: Access Token 재발급용 긴 수명의 보조 토큰.
4. **`JwtTokenProvider` 유틸리티 클래스의 역할**:
   - **토큰 생성기 & 수문장 역할**:
     - `createAccessToken()`: 30분 만료의 JWT에 회원 ID(`runnerId`)와 닉네임을 담아 생성
     - `createRefreshToken()`: 14일 만료의 탈퇴/로그아웃 관리용 토큰 생성
     - `getRunnerIdFromToken()`: 복호화하여 클라이언트가 보낸 토큰에서 러너 ID 추출
     - `validateToken()`: 위변조, 기간만료, 형식오류 등을 슬기롭게 예외처리(Handling)하여 검증
