# 러닝화 수명 관리 기능 개발 명세서 (Running Shoes Management)

**문서 작성일**: 2026년 8월 21일  
**작성자**: Running Coach 서비스 개발팀  
**목적**: 슬로우 러너 및 부상 방지를 위한 러닝화 수명(마모도) 트래킹 기능 구현 명세  

---

## 1. 기능 개요 및 비즈니스 목적

### 1.1 배경
* 러닝화의 쿠션 및 미드솔 반발력이 수명을 다하면 무릎 관절, 발목, 족저근막 등에 직접적인 충격이 가해져 부상 위험이 급증합니다. (통상 러닝화 수명: 500km ~ 800km)
* **목적**:
  1. 러닝화 등록 시 **구매/착용 시작일**과 **착용 비중(70%, 50%, 100%)**을 바탕으로 과거 러닝 기록 기반 **예상 누적 거리를 프리뷰 계산하여 자동 제안**하고, 사용자가 확인 및 수정할 수 있도록 지원합니다.
  2. 러닝 기록 등록 시 착용한 러닝화를 선택하면 누적 거리가 자동 가산(`+`)되고, 대시보드 및 통계 화면에서 **수명 잔여율(%) 및 교체 알림**을 제공합니다.

## 2. 데이터베이스 스키마 설계 (DDL)

### 2.1 신규 테이블: `RUNNING_SHOES` (러닝화 관리)

```sql
CREATE TABLE RUNNING_SHOES (
    shoe_id              BIGINT GENERATED BY DEFAULT AS IDENTITY NOT NULL,
    runner_id            BIGINT NOT NULL,
    shoe_name            VARCHAR(100) NOT NULL,                                -- 러닝화 모델명 (예: 나이키 페가수스 40)
    brand                VARCHAR(50),                                         -- 브랜드명 (선택, 예: Nike, Asics)
    max_distance_km      NUMERIC(6,2) DEFAULT 600.00 NOT NULL,                 -- 목표 수명 (기본값: 600.00km)
    current_distance_km  NUMERIC(6,2) DEFAULT 0.00 NOT NULL,                   -- 현재 누적 주행 거리 (km)
    is_default           BOOLEAN DEFAULT FALSE NOT NULL,                       -- 기본 대표 러닝화 여부
    is_retired           BOOLEAN DEFAULT FALSE NOT NULL,                       -- 사용 중단(은퇴) 여부
    purchased_date       DATE,                                                 -- 구매일 또는 착용 시작일
    created_at           TIMESTAMP DEFAULT CURRENT_TIMESTAMP NOT NULL,
    updated_at           TIMESTAMP,
    CONSTRAINT PK_RUNNING_SHOES PRIMARY KEY (shoe_id),
    CONSTRAINT FK_SHOES_RUNNER FOREIGN KEY (runner_id) REFERENCES RUNNER(runner_id) ON DELETE CASCADE
);

CREATE INDEX IDX_RUNNING_SHOES_01 ON RUNNING_SHOES(runner_id, is_retired);
```

### 2.2 기존 테이블 수정: `RUN_RECORD`

## 3. 핵심 비즈니스 로직 & 계산 공식

### 3.1 러닝화 최초 등록 시 "예상 누적 거리 프리뷰" 계산

사용자가 신발 등록 화면에서 `구매일(purchased_date)`과 `주 사용 비율(usage_ratio)`을 선택하면, 백엔드는 과거 기록을 기반으로 예상 누적 거리를 계산하여 프론트엔드로 반환합니다.

#### 🧮 계산 알고리즘
1. **대상 기록 합산**:
   * 조건: `runner_id = :runnerId` AND `run_date >= :purchasedDate`
   * 총 거리 $K_{total} = \sum \text{distance\_km}$
2. **착용 비중 가중치($W$) 적용**:
   * `100% (매일 이 신발만 착용)`: $W = 1.0$
   * `70% (메인 러닝화로 자주 착용)`: $W = 0.7$ *(기본 추천값)*
   * `50% (다른 신발과 번갈아 착용)`: $W = 0.5$
   * `30% (가끔 착용 / 서브 신발)`: $W = 0.3$
3. **최종 추천 누적 거리**:
   $$\text{Preview Distance} = \text{round}(K_{total} \times W, 1)$$

> **UX 처리**: 유저에게 계산된 추천값(예: `350.0 km`)을 인풋 필드에 기본 세팅해 주고, 유저가 필요 시 직접 숫자를 수정(예: `320.0 km`)하여 최종 저장할 수 있도록 함.

---

### 3.2 러닝 기록 등록/수정/삭제 시 누적 거리 동기화

* **러닝 기록 등록 (`POST /api/v1/runs`)**:
  * `shoe_id`가 선택된 경우:
    $$\text{RUNNING\_SHOES.current\_distance\_km} \leftarrow \text{current\_distance\_km} + \text{run.distance\_km}$$
* **러닝 기록 수정 (`PUT /api/v1/runs/{id}`)**:
  * 신발이 변경되었거나 거리가 변경된 경우:
    * 이전 신발: 이전 거리만큼 차감(`-`)
    * 변경된 신발: 새 거리만큼 가산(`+`)
* **러닝 기록 삭제 (`DELETE /api/v1/runs/{id}`)**:
  * 매핑된 신발: 삭제된 기록의 거리만큼 차감(`-`)

---

### 3.3 수명 상태 판정 및 통계 지표

* **수명 사용률(%)**:
  $$\text{Usage Rate (\%)} = \left(\frac{\text{current\_distance\_km}}{\text{max\_distance\_km}}\right) \times 100$$
* **상태 분류**:
  * `SAFE (안전, 0% ~ 79%)`: 정상 착용 (녹색 배지)
  * `WARNING (주의, 80% ~ 89%)`: 마모 진행, 교체 준비 (노란색 배지)
  * `DANGER (위험, 90% 이상)`: 쿠션 수명 한계 (빨간색 배지, 관절 보호 알림 발생)

## 4. 백엔드 REST API 명세 (Spring Boot)

### 4.1 러닝화 예상 누적거리 프리뷰 조회
* **Endpoint**: `GET /api/v1/shoes/preview-distance`
* **Query Parameters**:
  * `purchasedDate` (String, `YYYY-MM-DD`, 필수): 착용 시작일
  * `usageRatio` (Float, `0.3 | 0.5 | 0.7 | 1.0`, 필수): 착용 비중
* **Response Body**:
  ```json
  {
    "success": true,
    "message": "예상 누적 거리 계산 성공",
    "data": {
      "totalPeriodDistanceKm": 500.0,
      "usageRatio": 0.7,
      "estimatedDistanceKm": 350.0
    }
  }
  ```

---

### 4.2 러닝화 신규 등록
* **Endpoint**: `POST /api/v1/shoes`
* **Request Body**:
  ```json
  {
    "shoeName": "나이키 페가수스 40",
    "brand": "Nike",
    "purchasedDate": "2024-01-01",
    "maxDistanceKm": 600.0,
    "initialDistanceKm": 350.0,
    "isDefault": true
  }
  ```
* **비즈니스 처리**:
  * `isDefault = true`인 경우, 기존의 다른 기본 신발은 `isDefault = false`로 일괄 변경.
  * `current_distance_km`을 `initialDistanceKm`으로 초기화하여 INSERT.
* **Response Body**:
  ```json
  {
    "success": true,
    "message": "러닝화가 성공적으로 등록되었습니다.",
    "data": {
      "shoeId": 1,
      "shoeName": "나이키 페가수스 40",
      "currentDistanceKm": 350.0,
      "maxDistanceKm": 600.0,
      "usageRatePct": 58.3,
      "isDefault": true
    }
  }
  ```

---

### 4.4 러닝화 정보 및 최대 목표 수명 수정
* **Endpoint**: `PUT /api/v1/shoes/{id}`
* **Request Body**:
  ```json
  {
    "shoeName": "나이키 페가수스 40 (트랙 전용)",
    "brand": "Nike",
    "maxDistanceKm": 700.0,
    "currentDistanceKm": 420.5,
    "isDefault": true
  }
  ```
* **Response Body**:
  ```json
  {
    "success": true,
    "message": "러닝화 정보가 수정되었습니다."
  }
  ```

---

### 4.5 대표 러닝화 기본값 설정
* **Endpoint**: `PATCH /api/v1/shoes/{id}/default`
* **Response Body**:
  ```json
  {
    "success": true,
    "message": "대표 러닝화로 설정되었습니다."
  }
  ```

---

### 4.6 러닝화 은퇴 (사용 중단)
* **Endpoint**: `PATCH /api/v1/shoes/{id}/retire`
* **비즈니스 처리**: `is_retired = true`로 변경 (과거 러닝 기록 매핑 데이터는 그대로 보존).
* **Response Body**:
  ```json
  {
    "success": true,
    "message": "러닝화가 은퇴 처리되었습니다."
  }
  ```

## 5. UI/UX 화면 연동 가이드

### 5.1 러닝 기록 등록 화면 (`04_러닝_기록_등록_수정`)
* `[ 👟 러닝화 선택 ]` 드롭다운 컴포넌트 추가.
* 드롭다운 기본값은 `is_default = true`인 러닝화가 자동 선택됨.
* 옵션 목록 예시:
  * `[기본] 나이키 페가수스 40 (420km / 600km)`
  * `아식스 젤카야노 30 (150km / 700km)`
  * `신발 선택 안 함`

### 5.2 러닝화 관리 모달 / 페이지 (신규)
1. **상단**: 보유 러닝화 카드 그리드 (이름, 누적거리 게이지 바, 수명 %, 대표 배지, 수정/은퇴 버튼)
2. **신규 등록 모달**:
   * 신발명 입력 $\rightarrow$ 구매일 캘린더 선택 $\rightarrow$ 착용 비중 선택 (70%/50%/100%)
   * 추천 계산 거리(예: 350km) 자동 노출 $\rightarrow$ 사용자가 직접 수치 확인/수정 $\rightarrow$ 목표 수명(기본 600km) 입력 후 완료.

### 5.3 실시간 케어 & 대시보드 (`08_통계_분석`)
* 내 몸 피로 & 통증 케어 리포트 내 **러닝화 수명 위젯** 연동:
  * 표시 내용: `420km / 600km (70%)`
  * 90% 이상 도달 시 경고 배너 출력: *"러닝화 쿠션 수명이 90%에 도달했습니다. 무릎 관절 보호를 위해 러닝화 교체를 권장합니다!"*
